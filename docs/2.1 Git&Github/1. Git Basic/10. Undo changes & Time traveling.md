## Time travel



#### `git checkout <commit-hash>`

We can use git checkout to view a previous commit.

When using `git log` to view commit hashes, we just need the first 7 digits.

```shell
➜  Novel git:(main) ✗ git checkout 529bf25
Note: switching to '529bf25'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

If you want to create a new branch to retain commits you create, you may
do so (now or later) by using -c with the switch command. Example:

  git switch -c <new-branch-name>

Or undo this operation with:

  git switch -

Turn off this advice by setting config variable advice.detachedHead to false

HEAD is now at 529bf25 add more talking on chapter 1

➜  Novel git:(529bf25) git status
HEAD detached at 529bf25
nothing to commit, working tree clean
```



### detached HEAD state

- HEAD usually refers to a branch NOT a specific commit
- When we checkout a particular commit, HEAD points at that commit rather than at the branch pointer.
- What we can do:
  - Stay in detached HEAD to examine the contents of the old commit
  - Leave and go back to wherever you were before
  - Create a new branch and switch to it.



#### Referencing commits

- useful when to refer the last commit

```sh
git checkout HEAD~1 ## refers to the commit before HEAD 
git checkout HEAD~2
```

- useful when to switch back to the last branch

```sh
git switch -
```





## Discard changes

### Checkout

---

#### `git checkout HEAD <filename>`

#### `git checkout -- <filename>`

To discard any changes in that file, revering back to the HEAD



### ==Restore==

---

#### `git restore <filename>`

New git command to unmodifying files, do the same thing as `git checkout HEAD <filename>`

`git restore --source HEAD~1 <filename>`, restore to the commit before last commit



#### `git restore --staged <filenmae>`

- Remove file from ==staging area==

```sh
➜  UndoingDemo git:(main) git add .
➜  UndoingDemo git:(main) ✗ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   Secret.txt
        modified:   cat.txt
        modified:   dog.txt

➜  UndoingDemo git:(main) ✗ git restore --staged Secret.txt
➜  UndoingDemo git:(main) ✗ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        modified:   cat.txt
        modified:   dog.txt

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        Secret.txt
```



### Reset

---

#### `git reset <commit-hash>`

Reset the repo back to a specific commit. The commits between are ==deleted==. But associated changes are remained.

#### `git reset --hard <commit-hash>`

Reset both the commits and the changes. ==Everything is deleted==



### Revert

---

#### `git revert <commit-hash>`

Given one or more existing commits, revert the changes that the related patches introduce, and record some new commits that record them ==Go back to one of the old commit and create a new commit of the old version==

If you want to reverse some commits that other people already have on their machine, you should use revert.
