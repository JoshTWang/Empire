# Git stash

When I aim to switch to another branch with some changes that is trivial to commit, two different things may happen:

1. My changes come with me to the destination branch
2. Error if git detects conflicts



Git provides an easy way of stashing uncommitted changes so that we can return to them later, without having to make unnecessary commits.

> Use `git stash` when you want to record the current state of the working directory and the index, but want to go back to a clean working directory. The command saves your local modifications away and reverts the working directory to match the `HEAD` commit.



#### `git stash` or `git stash save`

Take all uncommitted changes (staged and unstaged) and stash them, reverting the changes in your working copy.

#### `git stash pop`

Remove the most recently stashed changes in your stash and reapply them to your working copy.

```shell
➜  StashingDemo git:(goodbye) ✗ git stash
Saved working directory and index state WIP on goodbye: b44e428 fix link bug

➜  StashingDemo git:(goodbye) git switch main  
Switched to branch 'main'

➜  StashingDemo git:(main) git switch goodbye 
Switched to branch 'goodbye'

➜  StashingDemo git:(goodbye) git stash pop
On branch goodbye
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   app.css
        modified:   index.html

no changes added to commit (use "git add" and/or "git commit -a")
Dropped refs/stash@{0} (36e9ce997d76e24b1700f7126f77d70a637e0d34)
```



### Multiple stashes

`git stash apply`

Apply without delete.

`git stash list`

`git stash apply stash@{<id>}`

`git stash drop stash@{<id>}`

`git stash clear`

```shell
StashingDemo git:(main) git stash list

StashingDemo git:(main) git stash apply stash@{0}

StashingDemo git:(main) git stash drop stash@{0}

StashingDemo git:(main) git stash clear
```
