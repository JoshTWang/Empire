# Git Tags

Tags are pointers that refer to particular points in Git history.

Tags are most often used to mark ==version releases== in projects. (e.g. 2.4.1)

Two types:

1. lightweight tags
2. annotated tags



#### [Semantic Versioning](https://semver.org/)

The semantic versioning spec outlines a standardized versioning system for software releases.
$$
X.Y.Z
$$
Z. Patch Release e.g. bug fixes

Y. Minor Release e.g. new feature

X. Major Release e.g. significant changes that is no longer backwards compatible



### Viewing Tags

#### `git tag`

Print a list of all the tags in the current repository.

#### `git tag -l "<tag-name>"`

- `git tag -l "*beta*"`

```sh
$ git tag
v16.9.0-alpha.0
v16.9.0-rc.0
v17.0.0
v17.0.1
v17.0.2
v18.0.0
v18.1.0
v18.2.0
```



### Checking Out tags

#### `git checkout <tag-name>`

- detached HEAD



### Differentiate tags

#### `git dif <tag1> <tag2>`



### Create tags

#### `git tag <tag-name>`

To create a lightweight tag. By default, Git will create the tag referring to the commit that HEAD is referencing.



#### `git tag -a <tag-name>`

To create a new annotated tag. Git will open your default text editor and prompt you for additional information.

We can also use `-m` option to pass a message directly.

#### `git show <tag-name>`

To show the detial of the tag



### Tagging Previous Commits

#### `git tag <tag-name> <commit-hash>`



### Moving Tags

#### `git tag - <tag-name> <commit-hash>`



### Deleting Tags

#### `git tag -d <tag-name>`



### Pushing Tags

By default, the `git push` command doesn't transfer tags to remote servers.

#### `git push <tag-name>`



#### `git push --tag`

To push all tags at once.
